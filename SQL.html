Requête 1)b :

Quels sont les produits de provenance des Etats-Unis avec un coût de moins de 25€ ? On veut connaître les noms et prix, le nom du fournisseur et sa ville.


SELECT Produit.NomProd, Produit.CoutAchat, Fournisseur.Societe, Fournisseur.Ville
FROM ((Produit
    INNER JOIN Fournisseur ON Produit.NoFour = Fournisseur.NoFour)
    INNER JOIN Pays ON Pays.NoPays = Fournisseur.NoPays)
WHERE (Pays.PaysEN = "United States")
    AND (Produit.CoutAchat < 25)
ORDER BY Produit.CoutAchat;

Requête 1)h :

Quels fournisseurs ne proposent que des desserts ?


SELECT DISTINCT f.NoFour, f.Societe, f.Ville
FROM (Fournisseur AS f
    INNER JOIN Produit AS p ON f.NoFour = p.NoFour)
    INNER JOIN Categorie AS c ON p.CodeCateg = c.CodeCateg
WHERE c.NomCateg LIKE "Dessert*"
    AND f.NoFour NOT IN (
        SELECT p2.NoFour
        FROM Produit AS p2
            INNER JOIN Categorie AS c2 ON p2.CodeCateg = c2.CodeCateg
        WHERE c2.NomCateg NOT LIKE "Dessert*")
ORDER BY f.Societe;

Explication : on garde les fournisseurs qui ont au moins un produit de la catégorie desserts, puis on exclut ceux qui ont aussi un produit d'une autre catégorie (sous-requête avec NOT IN).

Requête 1)j :

Pour optimiser les livraisons, quels couples de clients sont situés à Paris ?


SELECT c1.Societe AS Client1, c2.Societe AS Client2, c1.Ville
FROM Clientele AS c1
    INNER JOIN Clientele AS c2 ON c1.Ville = c2.Ville
WHERE c1.Ville = "Paris"
    AND c1.CodeCli < c2.CodeCli
ORDER BY c1.Societe, c2.Societe;

Explication : la table Clientele est utilisée deux fois (auto-jointure). La condition c1.CodeCli < c2.CodeCli évite de comparer un client avec lui-même et empêche les doublons (A-B et B-A).

Le résultat (extrait) :

Client1 Client2 Ville
... ... Paris
